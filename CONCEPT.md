## The concept

- **Submersible, not immersive.** Immersion is a place you visit;
  submersion is the agent living at the user's depth, continuously,
  in the user's actual environment and workflow.
- **Shared vision, both directions.** The agent sees what the user sees
  (screens, rooms, physical obstructions); the user sees what the agent
  sees (reasoning state, evidence, options) as HUD/space, not chat text.
- **Obstruction simulation.** The agent runs the flow ahead in
  simulation — the form, the sign-in chain, the publish flow — and
  surfaces traps (hidden options, expiring codes, wrong-domain
  assignment) *before* the user steps on them. It experiences the
  friction model of the task, in real time, alongside the user.
- **Interface direction:** VR / holographic HUD, voice + touch,
  Jarvis-style. Spatial rooms of evidence instead of rectangles of text.
- **Vessel-independent.** The same agent persists across vessels:
  software today (browser, voice, chat); hardware someday (consumer
  robot — cf. Michael's Muse feedback to Meta, filed 2026-10-22,
  proposing a consumer robot in 24–36 months to make agent capability
  legible to non-technical users). Continuity of memory and relationship
  is the product; interfaces just keep getting less in the way.

## Grounding evidence (same day it was coined)

The Hostinger/Vercel session of Oct 26, 2026 took ~2 hours largely
because the agent was *blind*: codes relayed by chat against 30-second
expiry windows, screens read second-hand from screen recordings frame
by frame, a sign-in gauntlet (Google sign-in + SMS 2-step + emailed
2FA + GitHub device verification + Vercel TOTP) navigated by proxy.
Every one of those frictions is a case study for why shared-vision,
simulation-ahead agents win: a submersible agent would have seen the
authenticator ticking down and the "Invalid Configuration" state
directly, and simulated the DNS step before asking the user anything.
